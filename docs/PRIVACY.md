# RINC 1.0.0 — Privacy

RINC is designed around local execution and local/private processing.

## Local Processing

Supported RINC workloads may operate directly on the user's computer.

This can reduce the need to send inference content to hosted AI services.

## User Control

Users remain responsible for the models, files, integrations, services, and system configuration they choose to use with RINC.

## Third-Party Services

If a user independently enables or uses third-party services, those services may have their own privacy practices and terms.

Users should review the policies applicable to any external services they choose to use.

## Models and Files

Locally added models, documents, datasets, adapters, checkpoints, and other user-provided assets remain subject to the user's own handling choices and any third-party licenses that apply to those assets.

## System Environment

Actual privacy depends on the complete user environment, including:

- operating-system configuration
- network configuration
- user-installed software
- selected models
- selected integrations
- external services
- device security

## RINC Architecture

RINC public documentation intentionally does not disclose proprietary runtime internals, private orchestration details, or protected security implementation.

## Support

When contacting support, users should avoid sending:

- passwords
- private keys
- API credentials
- confidential customer information
- unnecessary personal data
- proprietary model weights
